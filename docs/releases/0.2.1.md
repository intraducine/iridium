# Iridium 0.2.1

This experimental update combines the native runtime and Steam improvements with background downloads, launch argument editing and a choice of synchronization engines.

## Download

**Consolidated release preparation draft: a fresh 0.2.1 build is pending. No release or tag is created by this preparation.**

The planned sideloading file is **`Iridium-unsigned.ipa`**. A permanent download link will be added after an authorized build, package inspection and publication checks. Requires **iOS or iPadOS 18+**, JIT, and games you own.

## Install

1. When the build is available, sign the app and helper with a compatible sideloading tool, or import the IPA into LiveContainer using its supported JIT setup.
2. Open **Settings → Launch Support** to configure JIT. Use **Downloads → Steam** for owned Steam games, or **Add Game** to import a Windows game folder and executable.
3. Choose **Play**. To try another synchronization engine, choose **Settings → Runtime → Sync engine**, close Iridium from the app switcher and reopen it before playing.

Update the existing app or LiveContainer entry without deleting its data. Back up saves first. Repairs and updates retain older game copies; keep them until saves work in the new copy.

Standalone signing must preserve the increased-memory-limit entitlement in the final app signature and provisioning profile. The anonymous carrier does not grant installation or memory rights. LiveContainer uses the container process's signing and JIT rights. Both routes require device validation.

## What's new

- **Choose the sync engine.** Fastsync remains the default; Madsync and Wine standard sync are alternatives to test. Changes require a full restart. Existing runtime settings are preserved, and unreadable configuration is left unchanged.
- **Steam Cloud saves.** Opt in per game and account for supported Windows Auto-Cloud paths. First saves and conflicts require a side choice, replacements have backups, and uploads follow a confirmed game exit.
- **Background Steam downloads.** Standalone Iridium can transfer bounded encrypted batches over Wi-Fi on iOS 18+. Progress depends on iOS scheduling and processing time; reopening and explicitly resuming may be necessary. LiveContainer retains foreground downloads.
- **Download Live Activity.** See download state, verified progress and received transfer rate with the updated layout and background refresh handling. Received data still requires verification before installation.
- **Editable launch arguments.** Save per-game arguments from Game Options without changing other settings, and preview the parsed argument list.
- **Controller and session improvements.** Optional physical-controller keyboard/mouse mapping, input and reconnect fixes, safer launch/close handling, and Steam session persistence recovery.
- **Native runtime packaging.** The Madeira app omits the legacy Linux payload and retains its native Wine/FEX/DXMT runtime and required notices. A fresh package is needed to measure final size.

## Known issues

- The consolidated sync selector has not been tested with a game on a physical device. It does not establish a fix for launch stalls. Game compatibility, graphics, audio, video, input, saves and shutdown require separate testing.
- Sync modes are cached for the app process. Iridium blocks Play after a changed saved mode until it restarts. Prerequisite-installer sessions can use Wine standard sync even when Madsync is selected.
- Background downloads are opportunistic. Suspension, force-quit, network changes, authorization expiry and processing limits can stop progress. Real-account downloads, Cloud and device recovery remain unverified.
- Cloud supports verified Windows Auto-Cloud mappings only. Workshop, Steam Families discovery, protected branches, Steamworks/DRM and anti-cheat can require unsupported features.
- JIT and memory depend on the device and signing setup. Built-in JIT requires standalone Iridium, debugging permission, pairing and LocalDevVPN. Hosted Iridium uses external JIT.
